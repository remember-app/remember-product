## Важно: падения зависят от базы, и это не «грязное против чистого»

Две базы дают **разный набор падений**. Проверено сравнением схем: на стендовой миграции до 190, на `remember_review` сначала было только до 180. То есть «чистая база» была просто другой, а не более честной. После накатки 190 на `remember_review` падений стало не меньше, а больше.

**Поэтому падения разделены: часть — про схему и настройки, часть — про код.**

### Про схему и настройки — проявятся только там, где база другая

На `remember_review`:
- «expected 503 to be 200» — в двух тестах: сервис отвечает отказом, потому что на этой базе не настроено хранилище;
- «expected { error: 'storage not configured' } to match object [ … ]» — то же самое, прямо в тексте.

Это не код, а база без нужных настроек. На стендовой базе они не проявляются.

### Про код — падают на обеих базах

- **«a montage still being assembled carries its five stages in the list»** — `expected [ { stage: 'prep', … }, …4 ] to be null`. Этапы пришли там, где ожидался ноль: у собираемого ролика в списке их быть не должно. Падает везде, включая самую раннюю проверенную точку.
- **«repeating a montage that fell starts its journal from a clean sheet»** — `expected { lines: 2, stages: 5 } to deeply equal { lines: 2, stages: 2 }`. Повтор упавшего оставил **пять** строк этапов вместо двух. Это прямо по теме m-33: повтор должен начинать журнал с чистого листа (`journal.begin` затирает этапы на месте).
- **«the list of montages is every member's, and only a ready one carries a link»** — на стенде `expected { … } to match object { status: 'queued', … }`, на `remember_review` — 503. Значит на стендовой базе причина своя, и она не про схему.
