## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Если сборка споткнулась и воркер сам повторил её, журнал начинается заново, а приложение, которое читает его с места, где остановилось, не узнаёт, что старые записи исчезли, и показывает две попытки подряд.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Найдено кодером README api по TASK-253. Воркер при повторе задачи (journal.begin) стирает записи и возвращает этапы в ожидание, ролик при этом остаётся в работе; курсор приложения (наибольший id) остаётся, новые записи получают большие номера — старые остаются на экране. Редкое: нужен временный сбой сборки. Как узнать о повторе — по этапам (вернулись в pending) или по исчезновению записей; решать при разборе.
<!-- SECTION:NOTES:END -->
