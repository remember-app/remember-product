## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Сейчас сервер хранит одно пожелание к музыке на весь заказ. По новому макету пожелание пишется к каждому треку отдельно: заказ, шаблоны и итог заказа несут его вместе с треком, в описании контракта нет общего пожелания.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Контракт (решён лидом, воркер и приложение строят по нему): тело заказа — music_tracks: string[] как раньше + music_wishes: { [trackKey]: string }. params нового заказа: music_tracks всегда (как сейчас), music_wishes — только если есть непустое пожелание. Ответ шаблонов: у каждого шаблона music_wishes всегда есть (объект, {} если нечего сказать; у шаблона один трек — пожелание бывшей заметки шаблона ложится на него). Старое поле music_note: из тела заказа выпадает как любое неизвестное поле (removeAdditional сервиса, прецедент TASK-226), в новые params не пишется; в старых строках params остаётся как было — чтение не трогаем. Миграция не нужна (params — jsonb). Файлы: src/montages/order.ts, templates.ts, row.ts, summary.ts, view.ts, montages.ts, тесты рядом, docs/montages.md, README.
