## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Признак: EMAIL_LOGIN_DEV_BYPASS.** Включён при значении 1 или true (регистр и лишние пробелы не важны). Любое другое значение (0, no, пустое) и незаданная переменная — выключено: эта переменная единственная, что открывает дверь, поэтому непонятое значение оставляет её закрытой.

**Обход POST /auth/email/start без письма срабатывает только при всех трёх условиях сразу:**

1. признак включён;
2. адрес на домене test.com — проверяется хвост @test.com после normalizeEmail, так что x@evil.test.com не проходит;
3. NODE_ENV не production — сверка без учёта регистра и лишних пробелов, как была.

Нет хотя бы одного — обычный путь: письмо, а если почты нет — 503 mail not configured, и по-прежнему до создания пользователя, до выпуска токена и до траты лимита.

Ключи почты на обход больше не влияют (раньше обход жил только при ненастроенной почте): письмо на test.com всё равно некуда доставить, а на dev-машине с настоящими ключами это дало бы 502 вместо входа.

**Как читается.** Через тот же env() из src/auth/config.ts — новый механизм не заводился; сам ридер devEmailBypass() лежит там же, рядом с appleClientId и googleClientId. Отличие одно: присутствия значения мало, нужно явное «да».

**Файлы:** src/auth/config.ts (ридер), src/auth/plugin.ts (условие обхода), src/auth/auth.test.ts (замок), src/auth/testing.ts (уборка тестовых пользователей теперь по тегу, а не по домену — появились адреса на test.com), README.md, .env.example.

**Тесты.** Новый «the dev door: only test.com, only with the switch on, and never on absence» — без признака не проходит никто (ни обычный адрес, ни test.com), с непонятым значением тоже нет, с признаком обычный адрес и evil.test.com не проходят, а test.com проходит, и ссылка из ответа реально открывает сессию. Расширен «the lock: in production an unconfigured mailbox is still 503» — там признак включён нарочно, и всё равно 503 для обоих адресов и для трёх написаний production. В каждом отказе дополнительно проверено, что пользователь не завёлся.

Полный набор тестов api: **79 тестов, 8 файлов, зелено**. Коммит 378fbac, ветка worktree-agent-a04a766a24e2551ac репозитория projects/api (в main не влита).

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Обход почты сузился с «режим не боевой» до трёх условий сразу: **EMAIL_LOGIN_DEV_BYPASS=1** (или true), адрес на домене **test.com**, и NODE_ENV не production. Не задан признак — обхода нет ни для кого, что бы ни стояло в NODE_ENV и есть ли ключи почты. В боевом режиме обход невозможен ни при каком значении признака.

**Как включать в разработке:** положить EMAIL_LOGIN_DEV_BYPASS=1 в .env сервера api (или EMAIL_LOGIN_DEV_BYPASS=1 npm run dev) и входить адресом вида you@test.com — ссылка придёт прямо в ответе, как раньше. На любом другом адресе ссылки не будет: уйдёт письмо, а без ключей почты вернётся 503.

Сценарий разработки для команды не сломан, только сужен: та же ссылка в ответе, но теперь нужны переменная и адрес на test.com. README api (таблица переменных, раздел про почту, «Как добыть токен в разработке», описание POST /auth/email/start) и .env.example обновлены.
