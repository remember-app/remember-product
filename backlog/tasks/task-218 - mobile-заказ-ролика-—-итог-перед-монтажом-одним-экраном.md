ЭКРАН: шапка мастера вид «Итог» (без шкалы, «Назад» ведёт на нужный шаг, «Отмена»), заголовок «Всё готово к монтажу», афиша PosterOrder (три кадра, плашка шаблона с иконкой или без неё, если шаблона нет; длина крупно; справа формат словом и «16:9 · название воспоминания»), блок сводки BlockSummary с тремя секциями: «Кадры» («168 фото · 46 видео» и «от 5 человек» — числа из preview сервера, не считаются на телефоне; полоса из шести кадров — из тех, что войдут), «История» (текст на четыре строки с обрезкой; если не писали — секции нет или «режиссёр решит сам» по макету), «Музыка» (имя трека с волной; несколько — по списку, пусто — «Без музыки · живой звук»); строка с часами «Соберём примерно за N минут и пришлём уведомление» — N из estimate_minutes; главная кнопка «Начать монтаж». На итоге не правится ничего. Тап «Начать монтаж» заказывает ролик и ведёт на существующий экран ролика (см. контракт).
Края: preview отказал (409 мало материала / 400 длина вне предела после смены кадров) — понятное сообщение по-человечески и путь назад на нужный шаг, а не пустой экран; заказ отказал — то же, кнопка снова доступна; двойной тап по «Начать монтаж» не заказывает дважды.
Замечено кодером кита: сводка (№52 RowSummary) — в спеке ширина подписи 96, в ките 88, и кит рисует шеврон, которого спека не упоминает — решай по макету MontageSummary; правка кита в рамках этой карточки допустима.

КОНТРАКТ API (слит в main api, README «Ролики»; смотри README, здесь выжимка):
- POST /memories/:id/montages — заказ. Поля необязательные: target_seconds (целое, от min_seconds до max_seconds воспоминания), story_text, include_media_ids, exclude_media_ids, music_tracks (массив по порядку проигрывания: id полки bright|warm|calm|night|road и/или ключи своих загруженных треков music/<uuid>; пусто = без музыки — тогда в ролике живой звук видео), music_note (пожелания к трекам, ≤500, только вместе с треками, иначе 400), orientation. Старые music_track_id / music_track_key ещё принимаются — приложение их больше не шлёт. 400 на длину вне предела: {"error":"target_seconds out of range","min_seconds","max_seconds"}; 409 «мало материала»: {"ready_items","need"}.
- POST /memories/:id/montages/preview — тот же body, ничего не пишет. 200: {photos, videos, people, min_seconds, max_seconds, target_seconds, orientation, estimate_minutes}. Числа — по кадрам, которые войдут (готовые минус exclude_media_ids). Отказы те же, что у заказа. Предел длины и итог берутся ТОЛЬКО отсюда — приложение не считает их само.
- GET /memories/:id/montage-templates — только организатор. Шесть в порядке макета: {id, story_text, target_seconds, orientation, music_tracks, music_note|null}. id: for_myself, quick, report, short_form, parents, dopamine. Названия и подписи карточек шаблонов — в словаре приложения (ru и en, руками) по id; длина и формат на плитке («3:00 · 16:9») — из ответа. Длина шаблона уже зажата в предел по всему материалу; на шаге длины приложение перезажмёт её через preview с учётом исключённых кадров.
- Готовый заказ ведёт на существующий экран ролика (app/memory/[id]/montage/[montageId]) — веха M-27 превращает его в «монтаж в прямом эфире»; здесь ничего менять не нужно.
