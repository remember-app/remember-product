## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
doc-03 и decision-10: облачная нейросеть описывает кадры, узнаёт людей/животных, расшифровывает речь и строит план ролика; поставщик (Gemini или OpenAI) меняется настройкой, код от выбора не зависит; каждый запрос в нейросеть обязательно сохраняется вместе с ответом. Ключа от человека пока нет (decision-10 открыт) — живых вызовов быть не может, всё строится и проверяется на записанных ответах.

Нужен:
- общий интерфейс с методами, которые в этой вехе понадобятся следующим задачам: описать содержимое фото/видео (с учётом уже известного состава действующих лиц воспоминания — см. задачу «понимание кадров»), расшифровать речь в видео, построить план ролика по описаниям/расшифровкам/пожеланиям. Сигнатуры — на усмотрение исполнителя, но реализация задач-потребителей (T3/T3b/T4 этой вехи) не должна знать, Gemini за интерфейсом или OpenAI.
- два адаптера за этим интерфейсом — под Gemini и под OpenAI (настоящие HTTP-клиенты каждого API, а не заглушки), выбор — переменной окружения (например AI_PROVIDER=gemini|openai); без ключа в окружении — воркер это явно фиксирует в логе, а не падает и не делает вид, что вызвал нейросеть.
- один общий шлюз, через который проходит каждый вызов любого адаптера, и который до возврата результата пишет запрос и ответ в новую таблицу воркера (schema.sql, как jobs) — что запрошено, что получено, у какого поставщика и когда; таблица читаема запросом psql (эндпоинт наружу не нужен).
- тесты — на записанных ответах (фикстуры в репозитории), без единого обращения к сети; для этого HTTP-транспорт адаптеров должен подменяться в тестах.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Всё в projects/montage, коммит 1961881 в ветке worktree-agent-a7f096bf4b91ccd3e (слить в main сабмодуля — за лидом).

**Интерфейс (ai.py).** Шлюз `ai.AI(conn)` с тремя методами: `describe_media(blobs, cast, ref)` -> {"description", "cast"}, `transcribe_speech(blob, ref)` -> str, `plan_montage(shots, story, target_seconds, ref)` -> {"plan": [{"media_id", "seconds", "accent"}]}. Материал передаётся как `ai.Blob(mime_type, bytes)`. Промпты живут в ai.py (константы DESCRIBE/TRANSCRIBE/PLAN), а не у вызывающих, — иначе смена поставщика меняла бы и сам вопрос. Метки действующих лиц: cast уходит в промпт, модель узнаёт уже известного или заводит следующего (путь, предложенный в описании TASK-154). В plan_montage исключённые куски просто не попадают в shots, must_include — флаг на куске.

**Адаптеры.** Gemini — Interactions API (POST /v1beta/interactions, заголовок x-goog-api-key), видео уходит целиком; generateContent сознательно не берём: с июня 2026 это legacy-форма. OpenAI — Responses API (POST /v1/responses) плюс отдельная ручка /v1/audio/transcriptions с multipart-загрузкой файла; видео OpenAI не принимает вовсе, адаптер бросает ValueError — резать клип на кадры обязан вызывающий (TASK-154). Выбор — AI_PROVIDER=gemini|openai; ключ и модель — GEMINI_API_KEY/GEMINI_MODEL и OPENAI_API_KEY/OPENAI_MODEL (+OPENAI_TRANSCRIBE_MODEL, у OpenAI речь расшифровывает отдельная модель). Новый поставщик = класс с name/generate/transcribe и строка в PROVIDERS, ключ он получит по своему имени сам. Имена моделей по умолчанию (gemini-3.8-flash, gpt-5.5, gpt-4o-transcribe) вынесены в окружение: они меняются чаще кода.

**Журнал.** Новая таблица ai_requests в schema.sql (заводится тем же `worker.py init`). Строка заводится ДО обращения к модели (status=sent) и закрывается ответом (answered/failed) — воркер, убитый на полпути, всё равно оставляет запись о том, что спрашивали. Пропущенный вызов тоже строка: status=skipped, response пустой. В request лежат инструкция, промпт и по строчке на каждый приложенный файл (тип и размер): ни ключа, ни байтов медиа — на это есть отдельный тест. Готовый запрос для psql — в README.

**Без ключа.** `from_env()` возвращает None и пишет в лог, чего именно не хватает (AI_PROVIDER, <ИМЯ>_API_KEY, или поставщика с таким именем нет); каждый вызов пишет "<операция> skipped" и возвращает None — вызывающий откатывается на алгоритмический отбор, что и нужно TASK-156 AC#4. Воркер при старте печатает строку "cloud model: ...".

**Тесты.** test_ai.py, 15 проверок; ответы записаны руками по документации обоих API и лежат в fixtures/. Транспорт адаптера — параметр (callable, принимает urllib.request.Request), в тестах подменяется на отдающий фикстуру и запоминающий запрос, поэтому проверяется и то, что ушло бы в сеть. Половина про адаптеры прогнана отдельно с заглушенным socket.connect — зелёная. Полный набор репозитория: 61 passed (DATABASE_URL на remember_test, миграции API накатаны, MinIO с хоста).
