## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Сделано в сабмодуле api (ветка ворктри agent-a1f0080858c76ff05, коммит ca61728).

Миграция 050.do.contacts.sql: таблица contacts (owner_id, contact_id, created_at). PRIMARY KEY (owner_id, contact_id) — он же уникальность пары и индекс, по которому читается список; CHECK (owner_id <> contact_id); обе ссылки на users(id) ON DELETE CASCADE, поэтому удаление аккаунта уносит и его список, и его самого из чужих. Своего id у строки нет — на таблицу никто не ссылается, как в auth_identities.

Маршруты — src/contacts/contacts.ts, подключены в app.ts после authPlugin, только за app.authenticate:
- POST /me/contacts {username} — ник через findByUsername, 404 на несуществующий и на в принципе незанимаемый, 400 {"error":"cannot add yourself"} на себя, повтор — 200 и та же строка (on conflict do nothing). Ответ — те же три поля, что у GET /users.
- GET /me/contacts — только контакты вызывающего, по нику (citext, регистронезависимо).
- DELETE /me/contacts/:userId — 200 {"ok":true}; чужой контакт, уже удалённый и не-uuid — одинаковый 404.

Тесты — src/contacts/contacts.test.ts, 4 штуки, среди них отдельный на приватность: у A два контакта, под токеном B список пуст, удаление контакта A по id даёт 404 и список A цел; сохранение того же человека под B — своя независимая строка.

Краевое, решённое по ходу: порядок списка — по нику, а не по времени сохранения (список читают глазами, порядок не должен меняться от захода к заходу); не-uuid в DELETE — 404, а не 400, как в DELETE /memories/:memoryId/members/:userId; серверного поиска по списку нет по формулировке задачи.

README: раздел «Контакты — как это устроено» и три эндпоинта, плюс строка в «Устройстве».

AC 6 не отмечен намеренно: прогнана api-половина — npm test в воркте, 84/84 в 9 файлах (в том числе 4 новых), плюс lint и typecheck чистые. Целиком make test по трём сабпроектам не гонял: моя правка аддитивна и mobile/montage не трогает, а полный прогон — это пас тестировщика после мержа.
