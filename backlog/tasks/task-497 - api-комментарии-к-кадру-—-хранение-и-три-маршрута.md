## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Хранилище комментариев к кадру и три маршрута (doc-14). Сейчас их нет нигде: в мобильном нет поля,
в базе нет таблицы, обработчик читает пустоту.

## Что завести

Таблица комментариев к кадру — по мотивам migration 120 (лейблы). Колонки: `id` (uuid),
`media_id` (ссылка на `media_items` с каскадом — комментарий уходит вместе с кадром, это требование
doc-14, а не украшение), `memory_id` (для составных ссылок и для быстрого чтения по воспоминанию),
`author_id` (ссылка на `users` — «кто принёс кадр, уходит вместе с ним», тот же каскад, что у
`media_items.uploaded_by`), `body` (text, непустой, с потолком длины — сколько, реши сам и запиши
в `docs/media.md`), `created_at`.

Индекс по `(media_id, created_at)` — единственное чтение это «комментарии одного кадра по времени».

Миграция `190.do.frame-comments.sql` + `190.undo.frame-comments.sql`, по образцу 180 (идемпотентно,
номер с разрывом). Обратной совместимости нет (decision-19): никаких веток «а что если попадётся
старая строка».

## Маршруты

1. Чтение комментариев кадра. Либо отдельным `GET /memories/:memoryId/media/:mediaId/comments`,
   либо полем `comments` в уже существующем `GET .../media/:mediaId`. **Реши сам, но обоснуй в
   карточке**: у второго пути нет лишнего запроса, у первого — комментарии не тащат камеру и место
   при каждом открытии панели. Что выберешь, тем и объяснишь.
2. `POST /memories/:memoryId/media/:mediaId/comments` — написать. Тело `{"body":"…"}`.
3. `DELETE /memories/:memoryId/media/:memoryId/comments/:commentId` — снести свой.

Права — по матрице лейблов (decision-12, `docs/media.md` «Кто что может»). Читает любой участник,
`viewer` в том числе: комментарий виден всем, кто видит кадр. Пишет и удаляет свой любой участник,
`viewer` тоже — он участник воспоминания, а не гость; **если считаешь иначе, обоснуй в карточке,
это решение человека, а не твоё**. Чужой комментарий удалить нельзя никому, включая организатора.
