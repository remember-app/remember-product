## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Идёт после ревью (TASK-235): тестируется проверенный код. Автоматика сначала; ручную и визуальную проверку НЕ запускать — она гоняет реальный экран человека и делается только по его слову.
Где нет страховки (найдено при приёмке):
- api: нет теста, что ролик со СТАРЫМИ params (music_track_id / music_track_key, без music_tracks) виден в списке и повторяется (retry не проходит через checkOrder).
- api: сверка /montages/preview и /montages — один и тот же набор тел получает те же коды и те же тела отказов; эквивалентность оценки, границ min/max при исключённых кадрах и при воспоминании без готовых видео.
- api: шаблоны — каждый из шести проходит заказ как есть на воспоминании с малым материалом (длина зажата), на ru и en.
- montage: сквозной ролик со списком из своего и библиотечного трека под заказ длиннее базового; ролик без музыки — живой звук; повтор упавшего ролика старой формы; заказ на 600 с из материала с запасом (по арифметике кусков, живой прогон только короткий).
- mobile: сквозной путь по модели заказа — шаблон → автопилот → итог → заказ, и «руками» — до созданного ролика; «Стоп» посреди автопилота; отказы preview (409/400) ведут на нужный шаг.
Известное окружение: api-тесты гоняй с --fileParallelism=false в своей базе и своём хранилище; в worktree biome не видит файлов (.claude в исключениях) — линтуй пути явно; tsc в mobile требует свежих типов маршрутов (.expo/types/router.d.ts генерируется expo). Базу remember, MinIO, очередь и процессы человека не трогать.
