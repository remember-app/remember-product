## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Найдено M-22 при подготовке текста пользовательского соглашения: пункт «результаты разбора — описания кадров и расшифровки — хранятся у нас и удаляются вместе с кадром» сейчас неправда, и chief закрепил его в doc-03 «Done when».

TASK-154 и TASK-155 этой вехи завели в projects/montage/schema.sql свои таблицы media_understandings и media_speech, ключ — media_id текстом без внешнего ключа (осознанно: schema.sql воркера должен накатываться и на базу, где миграций api ещё не было). TASK-151 завела там же ai_requests — журнал каждого вызова нейросети, ref тоже media_id для сегодняшних двух типов задач (media_understanding, media_speech). removeMedia в src/media/gallery.ts удаляет media_items и снимает job media_preview по этому же id тем же способом (CTE, DELETE по id прямо в SQL api, хотя таблица не его — ровно как уже сделано для jobs) — но media_speech, media_understandings и ai_requests не трогает нигде: ни при удалении файла организатором, ни при выходе участника, ни при его исключении. Строки остаются висеть.

Добавить в тот же CTE removeMedia ещё три DELETE по id кадра (или id кадров пачкой) — media_speech, media_understandings, ai_requests where ref = id. Все три пути удаления медиа в этом файле проходят через один removeMedia, так что правка одна на все три.

Вне этой задачи (chief решит отдельно, когда до этого дойдёт): запись ai_requests от будущего режиссёра (TASK-156) будет касаться сразу многих кадров одним планом — ей нужен свой способ найтись по любому из них при удалении; заложено требованием в TASK-156.
