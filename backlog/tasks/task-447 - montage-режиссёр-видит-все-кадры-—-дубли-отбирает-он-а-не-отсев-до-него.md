## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Человек 2026-09-27: у него в воспоминании много почти одинаковых фотографий, и тратить на них время режиссёра и деньги не хочется. Значит отсев на этапе отбора кадров для ролика должен уверенно убирать дубли ДО режиссёра, а то, что до него дошло, дальше не режется.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Область: только projects/montage/montage/video/selection.py (Piece, _dedup); montage/video/frames.py при необходимости.
Внешний интерфейс _dedup(pieces, always=()) -> (kept, dropped) и сама Piece — не менять по сигнатуре так, чтобы
сломать director.py/choose() — они читают _dedup как есть, трогать их не нужно.

Сегодня серия схлопывается только по времени съёмки (DEDUP_SECONDS=2.0) — вообще без взгляда на содержимое
кадра. Отсюда две беды разом: то, что визуально почти одинаково, но снято с паузой (человек переснял через
5-10 секунд, ловя улыбку), в серию не попадает и лишним доходит до режиссёра; а то, что просто оказалось рядом
по времени, но по кадру разное, могло бы схлопнуться неправильно. «Сильнее и честнее» — это добавить проверку
самого кадра, а не просто раздвинуть окно по времени.

Подход (не требует новых зависимостей — pillow/numpy уже в requirements.txt):
- frames.sampled() уже возвращает сырые 96×54 серые кадры (по одному в секунду для видео, один — для фото);
  judge() уже вызывает best_moment() на этом же наборе. Сохрани кадр, соответствующий best_second (для фото —
  единственный), как новое необязательное поле Piece (например, thumbnail: bytes = b""), no default-value not
  breaking existing constructors.
- В _dedup: расширить окно кандидатов по времени (DEDUP_SECONDS сейчас 2.0 — тесно для ручной серии снимков) и
  внутри окна проверять визуальное сходство по этому же буферу (например, среднее абсолютное отклонение пикселей
  между двумя 96×54 массивами через numpy — дешёво, кадров в памяти воспоминания единицы-десятки). В одну серию
  схлопывать только то, что действительно похоже визуально; порог подбери и обоснуй на реальных примерах — можно
  сделать пару кадров-вариаций существующей fixture-фотографии (лёгкий сдвиг/кроп/яркость) для юнит-теста на
  «похоже» и «не похоже».
- Из серии в ролик по-прежнему идёт самый резкий (или включённый организатором — always побеждает как сегодня).

Не в этой задаче: TASK-446 (кадры, съеденные дедупом, пропадают из журнала) — известный смежный баг, отдельная
карточка, не в этой вехе. Не чини его тут и не расширяй эту задачу до него, но постарайся не сделать хуже: если
твои изменения того же места кода касаются, оставь короткую заметку в финальном отчёте, что заметил.

Тесты: расширить tests/test_selection.py — обе стороны (не мержит непохожее, мержит похожее вне старого 2-секундного
окна). Golden-снимок журнала (test_journal_golden.py) может не измениться, если это чистая внутренняя логика отсева;
проверь всё равно — docs/testing.md, MONTAGE_UPDATE_GOLDEN=1 при необходимости пересобрать снимок осознанно, не
вслепую.
