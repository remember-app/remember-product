## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Заказ ролика начинается с выбора из шести шаблонов. Тап по шаблону запускает автопилот: шаги сами листаются и заполняются, видно как, «Стоп» отдаёт руль. «Настроить самому» ведёт по шагам вручную.
<!-- SECTION:DESCRIPTION:END -->

АВТОПИЛОТ — в OrderProvider (src/order-wizard.tsx): auto (id шаблона или null), start(template), stop(). start заполняет order шаблоном через fromTemplate и одной async-прогулкой листает шаги, заполняя каждый на нём самом: frames (пауза) → story (печать посимвольно, не больше 40 штрихов по 30 мс) → music (треки по одному, затем пожелание) → build (длина едет к длине шаблона за 10 ходов) → summary, где setAuto(null) — итог уже человеку. Отмена сделана номером прогулки (flight в useRef): setTimeout не отозвать, поэтому после каждой паузы прогулка спрашивает, всё ли ещё она текущая; stop() двигает номер и гасит auto, второй start — тоже. При useReducedMotion печати нет совсем: каждое поле ложится целиком, любая пауза становится 400 мс (STEP_MS 240 / CALM_MS 400 по спеке, разделу 6). ownStory/ownLength остаются false — плашка шаблона и подпись «из шаблона» стоят, пока текст и длину не тронули рукой.

ШАПКА (критерий №9): WizardStep принимает step: number | 'summary' | 'templates'. Вид со шкалой — только у четырёх шагов; вход и итог идут вариантом кита без шкалы; «Отмена» рисуется везде, кроме итога (спека, вид «Итог» — справа пусто). «Назад» и «Отмена» сначала зовут stop(), потом делают своё; во время автопилота донный слой вместо «Дальше» — ActionBar со строкой «Собираю по шаблону» и кнопкой «Стоп» (secondary, ember по-прежнему один на поверхность).

МОДЕЛЬ (src/montage.ts, добавлением): TemplateFill = Omit<Order,'dropped'|'returned'|'seconds'> & {seconds:number} — всё, что решает шаблон, кроме кадров; fromTemplate(template) — ответ api в поля заказа (пожелание к музыке только при треках, иначе api отвечает 400; null → пустая строка).
