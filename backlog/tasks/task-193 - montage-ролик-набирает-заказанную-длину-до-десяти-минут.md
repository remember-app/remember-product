ИТОГ (исполнитель, 2026-09-21)

Сделано. Заказанная длина стала обещанием: общий шаг selection.stretch(pieces, target_seconds) после выбора, который montage.py зовёт один раз для обоих путей — и после director.direct, и после selection.choose, перед rhythm.fit. Не хватающие секунды делятся между клипами поровну, начиная с самого короткого файла (что один не может дать — отдают остальные), каждый клип растягивается через selection.cut_to вокруг того же лучшего момента максимум до целого файла. Фото не растягиваются. Склейки учтены: длина считается через assembly.length_of. Материала мало — ролик выходит короче, без ошибки; ничего отсеянного, исключённого или уже вошедшего ради длины не добавляется (шаг вообще не меняет состав кусков).

Где:
- selection.py — PHOTO_SECONDS 3.0 → 2.5 (число макета, по нему же API считает предел) и новая секция «the length that was ordered» с stretch.
- montage.py — один вызов selection.stretch после режиссёра/отбора, перед ритмом.
- rhythm.py — _room не срезает растянутый кусок: потолок max(MAX_PIECE_SECONDS, piece.seconds), клип по-прежнему ограничен своим файлом. Комментарий к HORIZON_SECONDS поправлен на десять минут. director.MAX_PIECE_SECONDS не трогал: растяжка идёт после плана, его потолок ограничивает только то, что просит модель.
- README.md — раздел «Заказанная длина» (правила, потолки, точность, поведение при нехватке материала), поправлены шаги 3 и 6 пайплайна и абзац про ритм.

Тесты: 157 зелёных (было 148). Новые — test_selection.py: заказы 60/300/600 в пределах ±5 % (не меньше ±3 с), заказ «всё, что есть» берёт все кадры целиком, равное деление секунд между клипами при нетронутом фото, нехватка материала = более короткий ролик, ничего отсеянного не возвращается ради длины. test_montage.py: два живых ролика — 20 с через отбор и 16 с через режиссёра по записанному плану. Обновлены ожидания длительности во всех живых тестах из-за фото 2,5 с. В сеть тесты не ходят.
