## Description

<!-- SECTION:DESCRIPTION:BEGIN -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Спека: doc-03 (длина — число секунд, предел «Σ видео + 2,5 с на фото, не больше 10 минут»), макет design/screens/MontageBuild.html. Сервис: projects/montage, README.

СЕЙЧАС воркер набирает не больше того, что даёт база: фото держится PHOTO_SECONDS=3.0, видео берётся одним куском CLIP_SECONDS=4.0 вокруг лучшего момента, ритм (rhythm.fit) зажимает кусок в [1.5, 6.0], режиссёр (director) — в [1.0, 8.0]. Заказ на 9 минут из 30 минутных видео соберёт ~2 минуты и промолчит. С этой карточки длина — обещание: api теперь принимает target_seconds до 600 (TASK-192), воркер обязан его выполнить, если материал позволяет.

ЧТО ДЕЛАТЬ (как — решает исполнитель, в границах критериев):
- Фото держится 2.5 с — это число из макета, по нему же api считает предел; ритм по-прежнему может сдвинуть на биты.
- Если отобранного при базовых длинах меньше заказанного, а неиспользованный материал ещё есть — сначала берётся он (choose уже так делает); если и всего отобранного мало — видео-куски растягиваются вплоть до целого файла (вокруг лучшего момента, в границах файла), поровну, пока не хватит длины или пока куски не станут целыми файлами. Фото не растягиваются.
- Растяжка работает и для пути через режиссёра (director.direct), и для пути отбора (selection.choose): общий шаг после выбора, чтобы ни один способ режиссуры не обходил его. Потолки rhythm.MAX_PIECE_SECONDS и director.MAX_PIECE_SECONDS не должны срезать растянутые куски.
- Склейки съедают 0.5 с каждая (assembly.length_of) — учесть, чтобы итог не оказывался короче заказанного на сумму склеек.
- Материала меньше, чем нужно, — не ошибка: ролик собирается короче, сколько есть.
- Не ломать: исключённые кадры не попадают никогда, «включить» попадает всегда, отсеянные отсевом кадры не возвращаются ради длины, порог MIN_ITEMS.
- Читается только params.target_seconds (float, до 600). Про шаблоны, музыку и итог воркеру знать нечего.

Тесты воркера в сеть не ходят (нейросеть подставлена). Тестовая база — своя, по README; базу remember, очередь, хранилище и процессы человека не трогать. Ничего не оставлять кроме результата (скрипты, контейнеры, файлы). Рядом идут другие вехи в тех же файлах (montage.py, director.py — журнал монтажа M-27; assembly.py — музыка, соседняя карточка): перед слиянием подтянуть main и не переписывать чужие места.
