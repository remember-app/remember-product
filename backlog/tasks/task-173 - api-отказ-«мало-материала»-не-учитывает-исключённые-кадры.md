## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
src/montages/montages.ts, заказ ролика: проверка «хватает ли материала» (ready < minReadyItems, 409) считает все ready-кадры воспоминания и происходит до того, как разбираются exclude_media_ids. Организатор, исключивший часть кадров, может пройти эту проверку с оставшимся числом ниже настоящего порога — ролик потом соберётся из двух кусков под заказ на минуту. Приложение уже подстраховывает то же самое на своей стороне (мастер гасит кнопку «Дальше», пока взятых меньше трёх) — chief просит одно правило и на сервере.

Порог должен считать ready-кадры за вычетом тех, что реально исключены этим же заказом (лежат в exclude_media_ids и существуют как ready-кадры этого воспоминания).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Порог считается после разбора и проверки списков, а не до них.

src/montages/montages.ts: блок подсчёта ready-медиа (409 «not enough material») переехал ниже — под проверку пересечения include/exclude и под проверку «такого готового кадра тут нет». К этому месту каждый id из exclude уже доказан как существующий отдельный ready-кадр этого воспоминания (незнакомые отсеяны 400, дубликаты сняты Set + lowercase), поэтому порог = count(ready) - exclude.length; отдельный SQL-фильтр не нужен. ready_items в теле 409 — остаток заказа, а не общее число кадров воспоминания: «2 при нужных 3» вместо бессмысленного «4 при нужных 3».

Следствие порядка: заказ, который одновременно называет чужой/неготовый кадр и не проходит по остатку, теперь отвечает 400 про кадр, а не 409. Иначе нельзя: пока списки не проверены, неизвестно, что вычитать. Отражено в README.

README: строка таблицы про 409 и абзац под ней описывают вычет и порядок проверок.

Тест (src/montages/montages.test.ts, тест про историю и выбор кадров): четыре ready-кадра, два в exclude → 409 с ready_items: 2, need: 3; стоит до общей проверки «ни один отказ не записал строку montages», так что заодно доказывает, что отказ не оставляет ни строки, ни задачи. Граница 4-1=3 → 201 уже покрыта существующим заказом с одним exclude.

Проверки: npm test — 99/99 зелёных; tsc --noEmit чисто; biome check по изменённым файлам чисто. Полный biome check по src выдаёт одну претензию к форматированию в src/memories/memories.test.ts — она была до этой работы, файл не трогался.
