## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
doc-03, Components: «Автоматический отсев брака как предложение» — до заказа ролика организатор видит, что автоматический анализ отметил как брак, и может это поправить (Done when). Экран выбора кадров (MontageSelect/SheetRejected) ждёт слияния библиотеки деталей (веха Afisha, m-21) — эта задача только про данные, без UI.

media_items (миграция api) получает поля результата отсева: отклонён ли кадр автоматическим анализом и почему (например, «размыто», «пере-/недоэкспонировано», «дубль другого кадра») — по образцу того, как уже устроены thumbnail_key/preview_key: заполняет воркер, api только читает и отдаёт. Поля видны там же, где остальные данные медиа (список галереи); не заполнено — «анализ ещё не готов», как остальные производные воркера.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Миграция migrations/060.do.media-screening.sql (+ undo): media_items += screening_rejected boolean, screening_reason text, обе nullable. 060 — следующий свободный номер после 050 на main; ветка своя, перед слиянием номер перепроверяет лид.

Контракт: оба поля null = анализ ещё не смотрел (сознательно не NOT NULL DEFAULT false — false читалось бы как «посмотрел и оставил»); reason null у оставленного кадра. CHECK на причину не ставил: словарь принадлежит воркеру (blurry / exposure / duplicate — ровно то, что montage уже меряет, — и что он научится видеть дальше), api его только переносит, и новая причина не должна требовать миграции из соседнего репозитория. Ограниченные CHECK-ом колонки в этой схеме — те, что пишет сам api.

Отдача: GET /memories/:memoryId/media, рядом с thumbnail_url/preview_url, без преобразования — select * уже забирает новые колонки, добавлены в тип MediaItem (src/media/upload.ts) и в тело ответа (src/media/gallery.ts). Других мест, где api отдаёт данные медиа, нет: маршруты /download отдают только ссылку.

Тест: в src/media/gallery.test.ts половина воркера, которая и так писалась рукой (thumbnail_key), теперь пишет и вердикт — проверено обе стороны: у обработанного кадра true/blurry, у нетронутого оба поля null. README — раздел GET /memories/:memoryId/media: пример ответа и абзац про отсев как предложение.

Зелёное: npm test 85/85, tsc --noEmit чисто, biome по src чисто (единственное замечание — предсуществующее форматирование в src/memories/memories.test.ts, не моё и не трогал).
