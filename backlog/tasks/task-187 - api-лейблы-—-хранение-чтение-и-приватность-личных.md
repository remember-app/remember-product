## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Сервер помнит лейблы воспоминания: название, цвет, общий или личный, и какие кадры в них лежат. Общий лейбл видят все участники воспоминания, личный — только хозяин. Галерея говорит, в каких лейблах лежит каждый кадр.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Есть лейбл (воспоминание, хозяин, название, цвет, общий или личный) и связь кадр↔лейбл: один кадр может лежать в нескольких лейблах, в одном и том же дважды — нет
- [ ] #2 Список лейблов воспоминания: любой участник, зрителя включая, получает общие лейблы и свои личные; у каждого — название, цвет, общий/личный, «мой ли», сколько кадров лежит. Чужие личные лейблы не приходят ни в списке, ни в подсчётах
- [ ] #3 Галерея: у каждого кадра список лейблов, в которых он лежит, — только тех, что видны спрашивающему. Состав и порядок галереи не меняются, кадр не дублируется, сколько бы лейблов на нём ни было
- [ ] #4 Кадр, удалённый из воспоминания (поштучно или уходом участника), пропадает из всех лейблов; сам лейбл остаётся. Лейбл не выходит за своё воспоминание
- [ ] #5 Приватность закреплена автотестом снаружи, через HTTP: второй участник не видит личный лейбл — ни название, ни состав, ни его следа в галерее; не участник воспоминания получает тот же ответ «не найдено», что и на остальных маршрутах воспоминания
- [ ] #6 Миграция с откатом, номер выше самого большого на main в момент слияния (не между существующими); README API описывает новые маршруты и поле в галерее
- [ ] #7 Автотесты api зелёные; прогнаны в своей тестовой базе, база человека и его хранилище не тронуты, за собой всё убрано
- [ ] #8 У связи кадр↔лейбл записано, кто положил кадр в лейбл (нужно, чтобы положивший мог его и убрать; если положивший ушёл, связь остаётся)
<!-- AC:END -->
