## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Когда два прогона проверок api идут одновременно (две вехи, две сессии), оба садятся на одну и ту же базу <DATABASE_URL>_test, и записи одного прогона попадают в чужой. Проверки, которые ждут задачу в queued, находят running, а очередь роликов считается на единицу больше. Видно на dev 2026-10-28: два полных прогона одного и того же коммита дали 2 красных, потом 1 красный, в разных файлах; те же проверки поодиночке зелёные, а на отдельно названной базе весь набор зелёный (30 файлов, 264 проверки). Это дефект изоляции прогонов — та же порода, что TASK-536, только не между прогоном и стендом, а между двумя прогонами.
<!-- SECTION:DESCRIPTION:END -->
