## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Для друзей нужен свой закрытый бакет Google (не общий бакет статики лендингов) и пара ключей для S3-совместимого доступа к нему. Заводит человек руками — ключей и бакета у нас нет.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Есть бакет только под Remember: закрытый, не публичный; регион и имя названы лиду
- [ ] #2 К бакету есть пара ключей S3-совместимого доступа (HMAC) с правом чтения, записи и удаления только в этом бакете; ключи положены человеком в инфраструктуру, где он держит секреты, а не в репозитории и не в переписке
- [ ] #3 Отдельно — второй маленький бакет (или папка с отдельными ключами) для проверок и тестов, чтобы пробы не задевали живой
- [ ] #4 Третий, отдельный бакет — только для снимков базы (закрытый), и свои ключи к нему с правом записи и чтения только в нём: если приживётся общая пара ключей с основным бакетом, потеря ключа унесёт и кадры, и снимки
- [ ] #5 Ключи и имена бакетов человек кладёт в файл вне всех репозиториев — ~/.remember-secrets.env (права 600), строками ИМЯ=значение: R2_ENDPOINT, R2_BUCKET, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, BACKUP_BUCKET, BACKUP_ACCESS_KEY_ID, BACKUP_SECRET_ACCESS_KEY, и бакет/ключи для проверок как R2_CHECK_BUCKET, R2_CHECK_ACCESS_KEY_ID, R2_CHECK_SECRET_ACCESS_KEY. Значения в чат, карточки и отчёты не идут
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Почему не cdn.dapp-devs.com: он общий со статикой лендингов, а там будут личные кадры друзей. Почему HMAC-ключи: у qe-life в инфраструктуре хранилище открывается родным ключом сервисного аккаунта Google, а не по S3 — наш код говорит по S3, ему нужна именно пара «ключ/секрет». Названия переменных в нашем коде остаются прежними (R2_*): их же читает стенд человека на маке.
<!-- SECTION:NOTES:END -->
