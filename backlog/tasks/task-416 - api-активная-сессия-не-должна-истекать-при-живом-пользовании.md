## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Вход по коду из письма дорогой — тянет за собой письмо. Сегодня сессия живёт ровно 30 дней с момента входа и умирает точно в срок, что бы человек ни делал в приложении: тогда его выкидывает на экран входа, и войти можно только заново через письмо (так сделали в m-27). Нужно, чтобы, пока человек живо пользуется приложением, сессия сама тихо продлевалась и не истекала у него из-под рук — выйти можно только явной кнопкой «Выйти» или отзывом сессии.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Сервис: projects/api (ветка dev). src/auth/session.ts: verify() сегодня только проверяет expires_at, не продлевает его. sessionTtlDays() (src/auth/config.ts, по умолчанию 30) — тот же срок использовать и для продления, новую настройку без нужды не заводить. verify() дёргается почти на каждый запрос — необязательно писать expires_at на каждый вызов, если дорого; например, продлевать только когда до истечения осталось меньше половины срока — порог на усмотрение. Мобильный клиент не трогать: он реагирует только на 401 (src/lib/auth.tsx) — это поведение остаётся как есть.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
verify() продлевает expires_at от текущего момента при каждом использовании живой сессии, но пишет не чаще раза в час (проверка и продление — один атомарный SQL через CTE, без лишних обращений к базе). Порог 'раз в час' выбран сознательно вместо 'меньше половины срока' — иначе активность на 10-й день из 30 позволяла бы истечь уже на 30-й, то есть после 20 дней простоя, а не 30. Продление не поднимает истёкшую и не отменяет отзыв (сигнал по WHERE только на живую строку). Три новых теста закрывают все случаи приёмки, включая тонкий: выход, случившийся ровно в момент, когда сессия была бы продлена, всё равно обрывает её. Мутационная проверка автора: со старым verify() тест 'сессия переживает срок' падает. Полный набор — 207 из 226 проходят; 19 падений — заранее существующие (хранилище, нужен MinIO/Docker, который на этой машине сейчас не поднимается — подтвердил сам, docker ps виснет); список падений до и после правки совпадает построчно. Слито в dev, worktree и ветка убраны.
