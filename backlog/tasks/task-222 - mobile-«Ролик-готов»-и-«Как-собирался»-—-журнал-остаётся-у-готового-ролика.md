## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Страница готового ролика: постер с кнопкой «смотреть», «Сохранить» и «Поделиться», и «Как собирался» — сколько просмотрели, сколько взяли, сколько склеек и все пять этапов; журнал остаётся у ролика навсегда, его открывает любой участник.

ВХОД (решение лида, chief может возразить): экран ролика — «страница» готового ролика, на неё ведёт тап по готовой карточке в блоке «Ролики» на ленте воспоминания (сейчас тап играет ролик прямо на ленте, TASK-207 оставляет то же). Иначе журнал готового ролика «потом» открыть нечем, а веха обещает, что «как собирался» открывает любой участник и после сборки. Плеер — нынешний, из ленты (слово chief: своего плеера не рисуем; «Смотреть» не ведёт в никуда): круглая кнопка play на постере запускает его. Поменять тап по готовой карточке на переход сюда — правка в файле ленты (src/memory/films.tsx или что от него останется после TASK-207): делается ПОСЛЕ слияния TASK-207 в main mobile, на свежем main. Кнопка «Сохранить и поделиться» на карточке остаётся как есть.
Шапка «Живая» без пилюли: «Ролик готов» / «<имя> · собран за N мин» — имя ролика: то, что заказ несёт (имя шаблона, если api его уже отдаёт — проверить в README api и в api.ts), иначе «Ролик на 2:30» из длительности; «собран за» — сумма времён этапов из журнала (started_at→finished_at), а нет журнала — только имя.
Постер 196 с меткой «Готов» и «2:30 · 16:9» (длительность и ориентация), две кнопки в ряд («Сохранить» accent и «Поделиться» обводкой — существующие действия скачивания/шеринга ролика, как в ленте), заголовок «Как собирался», три плитки-числа: «просмотрел» (файлов в отсеве — итог этапа), «взял в ролик» (итог режиссёрского этапа), «склеек» (итог сборки) — откуда брать числа, смотреть outcome в README api; список пяти этапов с галочками, итогом этапа и временем; тап по этапу → журнал этапа.
Ролик, собранный до журнала (или без него): экран без блока «Как собирался», кнопки и постер на месте, не ошибка. Читает любой участник, включая зрителя; «Сохранить»/«Поделиться» — как у соседей для тех, кому позволено.
Светлая тема подстановкой токенов по образцу HomeDay (слово chief); цель нажатия ≥ 44; подписи для экранного чтения; при «меньше движения» без анимаций. Тесты: с журналом, без журнала, зритель, переход на журнал этапа, переход на плеер. Живой стенд человека (api, воркер, база remember, симулятор) — не трогать; ручную и визуальную проверку человек делает сам.
Общие правила: strings.ts и api.ts правят все вехи — только добавлением; ГИТ: worktree (изолирован лидом), коммиты в его ветку, перед сдачей rebase на свежий main mobile и тесты заново; в main сливает лид.
