## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
В настройках воспоминания (doc-06) каждый участник в любой момент ставит себе «Планирует загрузить», «Всё загрузил» или «Ждать нечего»; сейчас сервер принимает только два последних и вернуться назад нельзя. Зрители — отдельная группа без статуса: в сводку не входят и статуса себе не ставят. Список людей отдаёт всё, что нужно экрану настроек.

POST /memories/:memoryId/contribution-status принимает три значения вместо двух: к done и nothing добавлен more_coming — на экране это «Планирует загрузить», и он же обратный путь из обоих. not_started не принимается: его оставляет приглашение, и рядом со статусом стоит число принесённых кадров, которое такому ответу противоречит. Зритель на этом маршруте получает 403 — единственный порог по роли, какой у статуса есть. Чужой статус не ставится по-прежнему никак: в маршруте нет :userId.

Ростер (GET /memories/:memoryId/members) отдаёт по каждому role, contribution_status и media_count. У зрителя contribution_status — null, а не значение из его строки; в базе она как была в not_started, так и осталась, наружу не идёт. media_count — сколько кадров человек принёс в это воспоминание, считается тем же предикатом, которым галерея показывает (всё, кроме pending_upload), поэтому сходится с тем, что видно глазами; раньше это считал клиент, вычитывая всю галерею (TASK-110).

Миграции нет: трёх значений из 010 хватило, новых не заводил.

Автоправило первой загрузки не тронуто — upload.ts по-прежнему уводит из not_started и nothing в more_coming и не трогает done; оба теста на это стоят зелёные. Тест на статус переписан прогулкой по всем трём значениям в обе стороны (под старым маршрутом падает на первом же more_coming), заведён тест на media_count по ростеру, в тесте ростера закреплён null у зрителя. «Зритель не входит в N из M» уже закреплён тестом TASK-166 в memories.test.ts.
