## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Сейчас режиссёр берёт клип целиком одним куском: в живом прогоне одно видео заняло десять секунд из тридцати. Он должен уметь взять из видео любой отрезок и несколько отрезков, если так лучше.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Область: только projects/montage — montage/ai/prompts.py (PLAN), montage/ai/answers.py (_step/planned),
montage/video/director.py, montage/video/story.py. Без изменений в selection.py, assembly.py, layout.py — они
уже готовы к нескольким кускам одного файла (Piece.start/seconds уже произвольны; layout.write пишет строку на
каждое появление, а не на media_id — см. её собственный докстринг «a file may legitimately stand in a video
twice»; journal.py уже несёт source_from_seconds/source_to_seconds на каждой записи), это подтверди тестами,
не переписывай.

Сегодня режиссёру показывается seconds_available = min(8, длина файла) — он не знает, что происходит в клипе
дальше восьмой секунды, и не может попросить кусок из середины или из двух разных мест. Нужно:
- В director._shot(): сообщать модели истинную длину клипа (без потолка в 8 секунд; разумный верхний предел на
  сам промпт — по характеру материала это короткие бытовые видео, не часы — можно ограничить, но не восемью
  секундами), чтобы у неё было из чего выбирать отрезок.
- В prompts.PLAN и answers._step(): шаг плана получает явные границы отрезка внутри файла (например,
  start_seconds и seconds — или start/end, как удобнее промпту), а не только длину куска от лучшего момента.
  Один и тот же media_id может встретиться в плане больше одного раза — с разными отрезками. answers.planned()
  не должен схлопывать повторы по media_id.
- В director.direct(): убрать дедупликацию плана по одному media_id (сейчас taken — set по media_id, который
  не пускает второе появление); дедуплировать нужно только буквально одинаковые шаги (тот же кусок, тот же
  отрезок), не по одной лишь метке файла. director._cut(): резать по явным границам шага, если они заданы (зажать
  в пределах реальной длины файла), и как раньше (центрируя на best_second) — если шаг границ не назвал.
- В story.plan(): laid — сейчас dict {media_id: piece}, переживёт только последний из нескольких кусков одного
  файла. Свяжи мысль режиссёра с конкретным взятым куском по порядку/по отрезку, а не только по media_id, чтобы
  каждый отрезок получил свою запись в журнале с верными source_from_seconds/source_to_seconds (колонки уже есть,
  ничего добавлять в схему не нужно).

Это АС#3 задачи («журнал показывает, какие отрезки взяты и почему») — уже написанное сегодня («беру 0:04–0:07»)
должно остаться верным на каждый отрезок отдельно, включая второй-третий отрезок одного клипа.

Golden-снимок журнала (tests/test_journal_golden.py, tests/fixtures/journal_director.json) почти наверняка
изменится — обнови его осознанно (docs/testing.md, MONTAGE_UPDATE_GOLDEN=1) и глазами проверь разницу, не
принимай её не глядя.

ВАЖНО: следующая задача этой вехи (TASK-448, звук куска) продолжит работу в этих же файлах (тот же шаг плана,
тот же промпт) — держи изменения по существу задачи и не переусложняй схему шага сверх того, что просят твои
акс, но и не закрывай дверь: TASK-448 добавит к шагу ещё один необязательный параметр (аудио-режим кусочка) тем
же путём.
