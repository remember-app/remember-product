Обработчик задачи montage — architecture.md «Montage-пайплайн», шаги 1-3 и 5-7 буквально; шаг 4 (отбор) без нейросетевого ранжирования (NIMA) по прямому решению человека — модель оценки кадра остаётся отдельным вопросом к нему (вес/происхождение/лицензия), пока делаем то, что модели не требует. ## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 1. Собрать все media_items воспоминания со status='ready' через ту же базу. Меньше 3 — не транзиентная ошибка: обработчик сам помечает montages.status='failed' с понятным error_text ('недостаточно материала для ролика' или похожим) и завершается штатно (без исключения) — job уходит в done, а не в три бесполезных повтора
- [ ] #2 2. Оригиналы скачиваются из R2 во временную папку (tempfile.TemporaryDirectory, как в media.py), убирается в finally/контекстном менеджере
- [ ] #3 3. Нормализация ffmpeg: общий холст 1080p, H.264, 30fps, единый звук, паддинг под вертикаль/горизонталь; фото превращается в неподвижный кадр нужной длины
- [ ] #4 4. Отбор без модели: сэмпл кадров видео (~1/сек), отсев размытых (дисперсия Лапласа) и пере-/недоэкспонированных (гистограмма), дедуп кадров в пределах ~2 сек по дате съёмки (нет даты — дедуп для этого файла пропускается). Порядок в готовом ролике — хронологический по captured_at с fallback на created_at (как уже сортирует галерея). Когда после отсева кандидатов больше, чем укладывается в target_seconds — выбрать топ по уже посчитанной резкости (Лапласу) как временной замене ранжированию; в коде явный комментарий/маркер, что здесь встанет NIMA отдельной задачей после решения человека по модели
- [ ] #5 5. Сборка ffmpeg: видео-клипы обрезаются до 3-5 сек вокруг лучшего момента, фото — 3 сек (статичный кадр или лёгкий Ken Burns — на усмотрение исполнителя), кросс-фейд ~0.5 сек между кусками; поверх — выбранный трек с fade in/out, звук исходных клипов приглушается/убирается (только музыка). Энкод 1080p H.264 + AAC, faststart
- [ ] #6 Каталог из 2-3 треков с фиксированными id 'warm', 'bright', 'calm' — сгенерированы самим ffmpeg (lavfi, тон/шум), без единого стороннего аудиофайла, чтобы не вставать в вопрос лицензии; неизвестный music_track_id — как недостаточно материала: сразу failed с понятным текстом, без повторов
- [ ] #7 6. Готовый файл выкладывается в R2 (например montages/<id>.mp4); воркер сам пишет montages.status='ready', video_key, duration_seconds в Postgres (как media_preview пишет media_items), затем вызывает POST {API_URL}/internal/montages/:id/ready с заголовком авторизации по общему секрету (INTERNAL_WORKER_TOKEN) — сбой этого вызова логируется предупреждением и не роняет job, строка в БД уже верна
- [ ] #8 Любая другая ошибка пайплайна (ffmpeg упал, R2 недоступен и т.п.) идёт по общему пути worker.py: retry с бэкоффом, после 3 попыток — новая ветка в run_once() по образцу media_preview вызывает give_up этого модуля, которая помечает montages.status='failed' текстом последней ошибки
- [ ] #9 Юнит-тест логики отбора на крохотных фикстурах (оценённые кадры → ожидаемый выбор), без реального ffmpeg
- [ ] #10 Живой e2e-тест по образцу test_media.py (фикстуры рисует ffmpeg на лету): 3 фото + короткий клип → играбельный MP4 нужной длины (ffprobe: длительность в разумном диапазоне, видео- и аудио-дорожки на месте); пропускается (skip), если таблицы montages ещё нет — как memory-фикстура test_media.py уже пропускает тесты без media_items
- [ ] #11 Все тесты воркера (старые и новые) зелёные через докер-раннер TASK-52; .env.example и README воркера получают API_URL и INTERNAL_WORKER_TOKEN
