## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Слова человека, doc-12, пункт без черновика: при открытии приложения, если человек уже вошёл,
не должно быть проыжков через онбординг.

По коду — не мелькает, а показывает: splash стоит до ответа `/me` (`_layout.tsx:126-128`), а при
сетевом сбое `fetchMe` падает, `user` остаётся null → статус `signed-out` → гейт уводит на
`/login`. Вошедший человек без сети видит экран входа. Токен при этом цел — он переиспользуется в
следующий запуск (зафиксировано тестом `auth.test.tsx:189-198`).

Корень один: `auth.tsx:96` ждёт сеть прежде, чем сказать «человек вошёл».

Границы: экран воспоминания и его лента — отдельная карточка, здесь не строить.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Деталь, меняющая объём: гейт держится на user целиком (auth.tsx:196-202) — без аккаунта статус не ready, а signed-out, и никакая правка таймаута это не спасёт. Значит класть копию аккаунта рядом с токеном и показывать экран сразу, обновив его фоном. Это маленькая правка в одном месте, а не «подкрутить splash».

Критерий #2 (настоящий отказ сервера всё равно уводит на вход) отсюда не выпадает: он защищает от того, чтобы тихая потеря сети стала тихим разлогином.
