## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Слова человека, doc-12, пункт без черновика: при открытии приложения, если человек уже вошёл,
не должно быть проыжков через онбординг.

По коду — не мелькает, а показывает: splash стоит до ответа `/me` (`_layout.tsx:126-128`), а при
сетевом сбое `fetchMe` падает, `user` остаётся null → статус `signed-out` → гейт уводит на
`/login`. Вошедший человек без сети видит экран входа. Токен при этом цел — он переиспользуется в
следующий запуск (зафиксировано тестом `auth.test.tsx:189-198`).

Корень один: `auth.tsx:96` ждёт сеть прежде, чем сказать «человек вошёл».

Гейт держится на `user` целиком (`auth.tsx:196-202`), поэтому копии аккаунта без этого правка не
обойдётся: она кладётся на телефон рядом с токеном и обновляется фоном. Копия обязана удаляться
везде, где удаляется токен — во всех трёх местах, что зовут `forget()` (`auth.tsx:104` отказ 401,
`:132` сессия умерла в полёте, `:167` «выйти» человеком). Иначе приложение откроется под
аккаунтом, из которого человек вышел. Отдельной пометки «копия устарела» не нужно: копия,
удаляемая вместе с токеном, не может пережить сессии, которой нет.

Границы: экран воспоминания и его лента — отдельная карточка, здесь не строить.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Копия стирается в forget() рядом с токеном, а не в местах вызова: forget() — единственное место, где удаляется токен во всём коде, и новый код, забывающий сессию, обязан идти через неё.

Проверено кодом, а не по памяти: SecureStore.deleteItemAsync вызывается ровно в одном месте — внутри forget() (auth.tsx:85). Три вызова forget() — это три повода (отказ 401, сессия умерла в полёте, «выйти» человеком), а не три места стирания. Прямых удалений токена в обход forget() нет ни одного.

Критерий #4 проверяет ровно то свойство, ради которого затевалось: выход из аккаунта, затем запуск — и копии на телефоне нет.
<!-- SECTION:NOTES:END -->
