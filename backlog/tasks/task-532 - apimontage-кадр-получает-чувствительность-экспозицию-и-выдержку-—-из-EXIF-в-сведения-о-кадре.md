## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Макет FrameInfo и design/README.md:262-264 обещают полосу настроек съёмки: ISO · мм · ev · ƒ · выдержка. Сегодня сервер отдаёт из оптики только фокусное и диафрагму — их пишет обработчик, читая EXIF. Чувствительности, экспозиции и выдержки нет нигде: ни в базе, ни в ответе, ни в том, что обработчик вычитывает из файла. Пока их нет, полосу рисовать нельзя — на экране не появляется ни пустой ячейки, ни нуля, ни догадки.

Что входит: обработчик читает из EXIF чувствительность, выдержку и экспозицию и пишет их кадру; api отдаёт их в сведениях о кадре. Это серверная часть, телефон без неё ничего не рисует.

Вне этого шага: рисование полосы на экране — отдельная карточка, которая ждёт этой.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Проверено ведущим перед постановкой.

Сейчас обработчик читает ровно семь вещей: montage/photo.py возвращает width, height, camera_model, focal_length_mm (FocalLength), aperture (FNumber), latitude, longitude. montage/media/frame_info.py держит это в одноимённом namedtuple FrameInfo и пишет одной UPDATE в media_items. Нужно расширить все три места плюс схему (projects/montage/schema.sql).

api: projects/api/src/media/frame.ts — тип и SELECT (строки 51 и 145), projects/api — миграция. Тип на телефоне — projects/mobile/src/api/media.ts (FrameInfo, строки 228-229, там же focal_length_mm и aperture).

Выдержка в EXIF пишется как дробь (1/60), и на полосе она должна читаться как «1/60 с» — форматbelongsтелефону, обработчик отдаёт число. экспозиция — знаковая, «0 ev», ноль это ноль, а не «неизвестно»; пусто и ноль — разные вещи, и их нельзя сливать (см. правило проекта про поля, которых нет).

Обратной совместимости нет (decision-19): база и хранилище будут снесены перед следующим деплоем, поэтому новые колонки добавляются обычной миграцией, без ничего для старых записей.

Решение ведущего по контракту, 2026-10-04 — нужно, потому что работа идёт двумя выдачами (сначала api, потом обработчик), и имена должны совпасть.

Колонки в media_items и ключи в ответе api одинаковые: iso, exposure_ev, shutter. Имена в стиле соседних (aperture, focal_length_mm), без единиц в имени — выдержка хранится дробью, а не секундами.

Все три nullable. Отсутствие значения — это null, а не ноль: ноль у экспозиции это настоящий ноль («0 ev»), и его нельзя сливать с «неизвестно». Телефон по правилу проекта поле, которого нет, не рисует.

Выдержка — дробь тем же текстом, что в EXIF: «1/60», «1/1», «0.5». Не число секунд. Число секунд на телефоне читалось бы как «0.02 с» и разошлось бы с макетом, который обещает «1/60 с», а чтобы из числа получить дробь, телефон должен был бы угадывать знаменатель обратно — это ровно та форматировка, которая не его дело. Форматирует телефон: печатает дробь как есть и дописывает « с».

Порядок выдач: сначала api (миграция и отдача), потом обработчик. Обработчик пишет UPDATE в те же колонки, что добавляет миграция api, и без неё его проверка не пройдёт — тестовая база накатывается миграциями api.
