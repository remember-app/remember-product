## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Нужен макету человека: design/screens/MemoryFrames.html и design/spec.md деталь №38 «Карточка ролика» — у собирающегося «3 из 5» и шкала из пяти полосок (кит CardMontage шкалу уже принимает). Сегодня список отдаёт только status; приложение не должно опрашивать журнал по каждой карточке — этап приходит в самом списке. Прошло ворота worth-doing (DO): один запрос на весь список к таблице montage_stages, заведённой TASK-200 (контракт — projects/api/README.md, «Журнал монтажа — как это устроено»).
Форма поля — на исполнителе, но: у ролика, который в очереди, в работе или упал, — состояния пяти этапов в порядке пайплайна (pending / running / done / failed) и по ним приложение само считает «N из 5»; у готового ролика и у ролика без строк этапов (ещё не начат воркером, собран до журнала) — пусто (null). Список остальных полей и порядок не менять. Только чтение; отметки «смотрит сейчас» этот маршрут не делает. Один запрос на весь список (не по запросу на ролик): роликов у воспоминания может быть много, список читается часто.
Файл списка — src/montages/montages.ts (там же правит веха Montage order: заказ, шаблоны — не трогать чужое, править только выдачу списка), тесты — рядом. README api — строка поля в разделе роликов.
ТЕСТЫ И СТЕНД: у человека поднят живой стенд, база remember и хранилище — его, не трогать; api/.env указывает на remember — с ним тесты не гонять. Своя база remember_m27_test на localhost:5432 (postgres/postgres); из worktree тесты — `npx vitest run --root <worktree>` после `npm run migrate` руками на своей базе, с DATABASE_URL, MONTAGE_SCHEMA_SQL (абсолютный путь к /Users/kubik/Nox/projects/remember/projects/montage/schema.sql), четырьмя R2_* и своим временным бакетом/контейнером MinIO (чужие бакеты не трогать; свои база, бакет и контейнер — удалить в конце); lint в worktree молча зелёный (biome исключает .claude) — прогнать по своим файлам временным конфигом вне репозитория. ## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Список роликов (GET /memories/:memoryId/montages) отдаёт у каждого незавершённого ролика поле stages — пять этапов пайплайна по порядку, у каждого своё состояние (pending/running/done/failed); карточка на ленте сама считает «3 из 5» и красит шкалу, журнал каждой карточки открывать не нужно. Этап, до которого воркер ещё не дошёл, приходит pending — полосок всегда пять. У готового ролика и у того, за который воркер ещё не брался (ни одной строки этапа), поле null. Этапы читаются одним запросом на весь список (ids незавершённых → один select к montage_stages); остальные поля и их порядок не тронуты, маршрут по-прежнему только читает и никого не отмечает смотрящим. Тест «a montage still being assembled carries its five stages in the list» в src/montages/montages.test.ts: идущий, упавший, готовый (со всеми пятью строками — всё равно null), ещё не начатый, все четыре одним списком; пин на порядок ключей ответа и на пустой montage_viewers. Описано в README api (раздел GET /memories/:memoryId/montages + уточнение в retry).
