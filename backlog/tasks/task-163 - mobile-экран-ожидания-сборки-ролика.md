## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
doc-03, макет «Афиша»: пока ролик собирается, организатор видит не просто карточку «processing» в общем списке (как сейчас), а отдельный экран прогресса. Вид, тексты и раскладка — design/spec.md раздел 8, экран MontageProgress, и design/screens/MontageProgress.html.

После успешного заказа (TASK-162 — мастер шлёт POST /memories/:memoryId/montages) вместо возврата к списку воспоминания открывается MontageProgress для этого ролика: мозаика/заливка/спиннер, «Собираем ролик», мета (длина · ориентация · число кадров), абзац «Приложение можно закрыть...», пять строк этапов (по спеке — готово/идёт/ждёт; сами этапы — что реально известно о состоянии, api не отдаёт пошаговый прогресс, только status ролика queued/processing/ready/failed, так что реалистичная детализация этапов — на ваше усмотрение технически, текст по спеке). Кнопка низа — «К воспоминанию», уходит на экран воспоминания, не отменяя сборку.

Ролик стал ready или failed, пока открыт этот экран, — обычное поведение приложения (список уже умеет подхватывать смену статуса, см. TASK-125) должно довести до соответствующего состояния, а не оставить человека на вечном спиннере.
<!-- SECTION:DESCRIPTION:END -->
