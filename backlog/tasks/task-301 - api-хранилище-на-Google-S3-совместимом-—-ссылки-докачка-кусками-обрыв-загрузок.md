## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Вместо Cloudflare R2 будет Google S3-совместимое хранилище. Протокол тот же, но мелочи расходятся; сервер должен работать с ним не «по надежде», а по проверке каждой операции.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Составлен перечень всех обращений api к хранилищу (начало многочастной загрузки, подписанная ссылка на часть, завершение, обрыв, размер файла, подписанная ссылка на скачивание, удаление) и против каждого записано, что документация Google говорит о совместимости; расхождения названы прямо, а не подразумеваются
- [ ] #2 Всё, что Google не принимает так, как R2, исправлено в коде; код по-прежнему работает и с локальным MinIO стенда, и с Google, без ветвления «если это Google» там, где можно обойтись общей формой запроса
- [ ] #3 Автотесты закрепляют обращения к хранилищу так, что тест краснеет, если запрос станет таким, который Google отвергает (лишние заголовки контрольных сумм, неподдерживаемый вызов и т.п.); зелёные на MinIO
- [ ] #4 Есть один запускаемый живой контроль на настоящем бакете (ключи только из окружения, не из репозитория): заявка → куски по подписанным ссылкам → докачка недостающего куска → завершение → размер → скачивание по ссылке → обрыв незавершённой загрузки → удаление. Он пишет только в бакет для проверок, чужие ключи не трогает, за собой убирает
- [ ] #5 Если живого бакета ещё нет — это сказано в отчёте прямо: какие пункты проверены только по документации и тестам, какие ждут бакета; догадка не выдаётся за проверку
- [ ] #6 docs/running.md и docs/media.md описывают работу с Google-хранилищем: значения переменных (без секретов), что там отличается, и как запустить живой контроль

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Сервис: projects/api, файл src/media/r2.ts (подпись — aws4fetch, адресация по пути <endpoint>/<bucket>/<key>, регион R2_REGION, сегодня auto), потребители src/media/upload.ts и src/media/gallery.ts (каскад удаления, обрыв загрузок). Переменные R2_ENDPOINT/R2_BUCKET/R2_ACCESS_KEY_ID/R2_SECRET_ACCESS_KEY/R2_REGION не переименовывать: их читает стенд человека на маке, он сейчас поднят. Что известно заранее и надо проверить, не принимая на веру (список не исчерпывающий): Google принимает подпись SigV4 только со своим адресом storage.googleapis.com и регионом auto; проверить многочастную загрузку и её обрыв, ответ 200 с ошибкой в теле при завершении, список незавершённых загрузок, срок жизни неоконченных загрузок у Google (сами ли чистятся, и не нужно ли правило у бакета), правило CORS не нужно для нативного клиента, но подтвердить. Бакет для живого контроля заводит человек (карточка «Человек: бакет Google…»); до неё живой контроль запустить нельзя — тогда работа сдаётся в состоянии «по документации и тестам», и лид дозапускает живую проверку сам. Нельзя трогать стенд человека на маке: его базу remember, MinIO, порты, живые процессы; тесты — только в своей тестовой базе и своём бакете.
<!-- SECTION:NOTES:END -->
