## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Сервер отдаёт шесть шаблонов ролика: у каждого своя история, музыка, длина и формат. Текст истории собирается из заготовки и данных воспоминания — названия, дат и числа участников — на языке организатора.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Спека: doc-03 («Шаблон ролика: шесть готовых … шаблон — текст истории, музыка, длина и формат разом»), макеты design/screens/MontageTemplate.html, MontageStory.html («Шаблон «Для родителей»»), MontageBuild.html («из шаблона «Для родителей»»). Сервис: projects/api, src/montages/ (новый файл templates.ts, маршрут монтируется рядом с остальными), README «Ролики». Ждёт TASK-192: берёт из него список треков, расчёт предела длины, id полки — не дублировать.

МАРШРУТ: GET /memories/:memoryId/montage-templates — только организатору (403 остальным, 404 не-участнику), как заказ. Ответ 200 — массив из шести в порядке макета:
{ "id", "story_text", "target_seconds", "orientation", "music_tracks": [...], "music_note": string|null }
Настроить самому — не шаблон: это пустой заказ, маршрут про него ничего не знает.

ШЕСТЬ (id → длина · ориентация, по макету; названия и подписи карточек живут в словаре приложения по id, сервер их не отдаёт):
- for_myself «Для себя» → 180 · landscape
- quick «Быстрый, энергичный» → 60 · landscape
- report «Официальный отчёт» → 120 · landscape
- short_form «TikTok · Reels · Shorts» → 30 · portrait
- parents «Для родителей» → 150 · landscape
- dopamine «Дофаминовая бомба» → 45 · portrait
Музыка — выбор лида по настроению, легко менять (одна таблица): for_myself [calm], quick [bright], report [calm], short_form [bright], parents [warm] (так в макете), dopamine [bright, road]. music_note — null, кроме случая, когда он что-то говорит.

ДЛИНА: target_seconds шаблона зажимается в [min_seconds, max_seconds] воспоминания по всему готовому материалу (исключённые ещё неизвестны — приложение перезажмёт на шаге длины через итог заказа). Шаблон 3:00 на воспоминании с 40 секундами материала отдаёт 40.

ТЕКСТ ИСТОРИИ собирается из заготовки шаблона и данных воспоминания: название, даты (одно число или период, по-человечески, на языке запросившего), число участников с вкладом (организатор + участники, зрители не считаются). Русский и английский оба написаны руками, английский не калька (doc-8): язык — users.language запросившего. Голос — как в образце макета («Ролик для родителей о свадьбе Лизы и Марка. Спокойный темп, каждый кадр держится подольше … Без резких склеек …»): что за ролик, какой темп, что главное, чего избегать. До 600 знаков (потолок текста в приложении), в 2000 api не упирается. Название воспоминания подставляется как есть, без интерпретации; ничего, чего сервер не знает (имена людей, «свадьба»), в текст не подставлять.

Тесты — по образцу montages.test.ts, в своей тестовой базе; базу remember, очередь, хранилище и процессы человека не трогать. Миграция не нужна; если понадобится — номер выше самого большого на main. Ничего не оставлять кроме результата.
