## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Сделано: GET /memories/:memoryId/montage-templates — шесть готовых роликов в порядке макета, только организатору (403 остальным, 404 не участнику). Ответ: id, story_text, target_seconds, orientation, music_tracks, music_note. Своих таблиц и миграции нет: шаблон — это заранее заполненное тело заказа, приложение шлёт его в POST montages, выбросив id. «Настроить самому» не отдаётся, названия карточек тоже (словарь приложения по id).

Где: projects/api — новый src/montages/templates.ts (маршрут, таблица шести, заготовки историй), монтируется из src/app.ts рядом с montageRoutes; README, новый раздел «GET /memories/:memoryId/montage-templates» перед разделом про заказ. Длина зажимается общим materialLeft из montages.ts, полка треков — musicTracks оттуда же; ничего из TASK-192 не продублировано.

Решения внутри задачи: (1) текст истории влезает в 600 знаков без обрезки в коде — заготовки написаны так, что с названием в 200 символов максимум выходит 518; держит это тест, обрезка была бы мёртвой веткой; (2) даты собираются Intl.DateTimeFormat.formatRange (одно число и период одним куском, ru-RU / en-GB), день считается по UTC — часового пояса воспоминание не хранит, помечено ponytail-комментарием; (3) число участников — организатор и участники, зрители не в счёт, тот же счёт, что у карточки на главном экране; (4) music_note есть у parents и dopamine, у остальных null.

Тесты: src/montages/templates.test.ts, 7 тестов — порядок и состав шести, зажим длины (3:00 при 40 с материала = 40), сборка текста на обоих языках с названием/датами/числом людей, период и единственное число, потолок 600 при названии в 200 символов, права (403/403/404/404/401), и что каждый из шести проходит заказом как есть с 201. Прогон в своей тестовой базе и своём MinIO (контейнеры t198-pg/t198-minio, удалены): вся пачка 14 файлов / 129 тестов зелёная, tsc --noEmit чисто, biome чисто.
