## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Найдено при приёмке TASK-468 (2026-10-04).

В итоге этапа «Сборка» воркер пишет ключ `cuts` — число склеек в ролике (`montage/video/montage.py`, около строки 431). Проверено по трём местам:

- **в контракте api его нет.** В `projects/api/docs/journal.md` раздел «Этапы», подраздел `assembly`, перечислены только `percent`, `steps` и `seconds`;
- **приложение его не читает.** Поиск по `projects/mobile/src/lib/montage/` не находит ни одного обращения к `outcome.cuts`;
- **тесты его не проверяют** — ни в api, ни в воркере.

То есть ключ, который никто не читает и никто не обещал. Он остался с прошлых времён, когда сборка отдавала число склеек вместо подшагов и процента.

Почему это стоит убрать, а не оставить «на всякий случай»: решение-19 отменяет обратную совместимость, а лишний ключ в `jsonb` без `CHECK` — это число, которое ничем не подтверждено. Через месяц оно будет выглядеть как часть контракта: кто-то откроет снимок, увидит `cuts` рядом с `percent` и `steps` и будет искать, кому он принадлежит и почему расходится с числом подшагов.

Стоит ли убирать в рамках TASK-489 (пересъёмка эталона) или отдельно — на усмотрение: к пересъёмке это всё равно придётся, раз снимок перезаписывается.
