## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Основание — чтение документации Google (TASK-300 переписана под JSON-ключ). Схема проверки: токен — JWT RS256 из JSON-ключа (scope devstorage.read_write, обмен на https://oauth2.googleapis.com/token), запросы сервера — заголовок Authorization: Bearer к https://storage.googleapis.com с адресацией по пути /бакет/ключ; подписанная ссылка — V4 GOOG4-RSA-SHA256: канонический запрос PUT, путь /бакет/ключ, query отсортирован лексикографически (X-Goog-Algorithm, X-Goog-Credential=<client_email>/<ДАТА>/auto/storage/goog4_request, X-Goog-Date, X-Goog-Expires не более 604800, X-Goog-SignedHeaders=host, partNumber, uploadId), подписанные заголовки host, полезная нагрузка UNSIGNED-PAYLOAD, подпись RSA-SHA256 закрытым ключом в hex. Начало и завершение подписанной ссылкой сделать нельзя — их делает сервер с токеном. Эмулятора для многочастной загрузки нет, поэтому проверка только на настоящем бакете. Скрипт писать в своём worktree на Node (node:crypto, fetch), без новых зависимостей и не коммитить.

РЕШЕНИЕ decision-16 (2026-09-25): хранилище ВРЕМЕННОЕ — общий бакет компании cdn.dapp-devs.com; всё наше строго под префиксами remember/dev-media/ (основная) и remember/dev-check/ (проверки), ни одного объекта вне них — чужое рядом, промах дорогой. Бакет публичный, поэтому единственная защита кадра — длина и случайность пути: имена объектов — только неугадываемые (uuid), никаких порядковых имён. Ключ — JSON служебной учётки компании в ~/.remember-secrets.gcs.json (кладёт человек, TASK-347); настройки: GOOGLE_STORAGE_BUCKET=cdn.dapp-devs.com, префикс основной remember/dev-media, префикс проверок remember/dev-check. Перенос на своё хранилище — потом и, возможно: поэтому префикс задаётся настройкой и добавляется в одном месте драйвера (в БД остаются прежние логические ключи).

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Живая проверка на настоящем Google (cdn.dapp-devs.com, только под remember/dev-check/<uuid>/, после прогона 0 объектов и 0 незавершённых загрузок): ссылка V4 GOOG4-RSA-SHA256 на часть многочастной загрузки, подписанная закрытым ключом (partNumber и uploadId внутри подписи, подписан только host, регион auto), принимается Google без токена; вся цепочка прошла с первой попытки: токен из JSON-ключа → начало с Bearer → две части по подписанным ссылкам → завершение → HEAD (размер точный) → GET по подписанной ссылке (хеш совпал) → удаление; обрыв незавершённой загрузки 204, часть после обрыва 404 NoSuchUpload; повторный обрыв 204 (безопасен); обрыв завершённой загрузки 204, объект цел. ВАЖНО для приложения: просроченная подписанная ссылка на часть — НЕ 403, а 400 ExpiredToken; неверная подпись — 403 SignatureDoesNotMatch. Приложение сегодня заново просит ссылки только по 403 (src/lib/upload/send.ts) — правка вынесена в TASK-351. Приложение по схеме не переписывается.
