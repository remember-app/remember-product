## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Первым делом после получения бакетов и JSON-ключа — короткая живая проверка того, что неизвестно по документации: можно ли выдать телефону ссылку на часть многочастной загрузки, подписанную закрытым ключом служебной учётки. Ответ решает, переписываем ли мы только сервер или ещё и приложение.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 На проверочном бакете (не на основном) прогнана вся цепочка на настоящем Google, каждый шаг записан как «прошёл / не прошёл / что ответил Google»: (1) сервер получает токен доступа из JSON-ключа и начинает многочастную загрузку с ним; (2) сервер выдаёт ссылку на PUT части с подписью закрытым ключом (partNumber и uploadId внутри подписи, подписан только заголовок host, регион auto), и curl БЕЗ токена заливает по ней часть и получает ETag — для двух частей, где первая не меньше 5 МиБ; (3) сервер завершает загрузку с токеном, HEAD показывает верный размер, ссылка на скачивание, подписанная тем же ключом, отдаёт те же байты, удаление объекта работает; (4) незавершённая загрузка обрывается и после этого её часть больше не принимается

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Основание — чтение документации Google (TASK-300 переписана под JSON-ключ). Схема проверки: токен — JWT RS256 из JSON-ключа (scope devstorage.read_write, обмен на https://oauth2.googleapis.com/token), запросы сервера — заголовок Authorization: Bearer к https://storage.googleapis.com с адресацией по пути /бакет/ключ; подписанная ссылка — V4 GOOG4-RSA-SHA256: канонический запрос PUT, путь /бакет/ключ, query отсортирован лексикографически (X-Goog-Algorithm, X-Goog-Credential=<client_email>/<ДАТА>/auto/storage/goog4_request, X-Goog-Date, X-Goog-Expires не более 604800, X-Goog-SignedHeaders=host, partNumber, uploadId), подписанные заголовки host, полезная нагрузка UNSIGNED-PAYLOAD, подпись RSA-SHA256 закрытым ключом в hex. Начало и завершение подписанной ссылкой сделать нельзя — их делает сервер с токеном. Эмулятора для многочастной загрузки нет, поэтому проверка только на настоящем бакете. Скрипт писать в своём worktree на Node (node:crypto, fetch), без новых зависимостей и не коммитить.
