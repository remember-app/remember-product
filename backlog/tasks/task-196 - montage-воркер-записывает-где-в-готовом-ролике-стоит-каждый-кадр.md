Воркер пишет раскладку ролика в `montage_frames` (таблица API, его миграция 100.do.frame-info.sql) — строка на каждое появление кадра: ролик, кадр, секунда начала, длительность. Секунды считаются так же, как их раскладывает сборка: каждый стык съедает полсекунды кросс-фейда. Пишется сразу после подгонки в ритм (rhythm.fit), когда длины окончательные, — как просила веха «Монтаж в прямом эфире»; и второй раз по нормализованным клипам, длины которых сборка измеряет, а не берёт на слово, — чтобы раскладка совпадала с файлом, а не с планом. Пересборка того же заказа сначала удаляет свои строки; удаление и вставка идут одной транзакцией, чтобы живой журнал не увидел между ними пустоту. Сбой записи ролик не роняет: предупреждение в лог, сборка идёт дальше. Своей копии таблицы веха не заводит.

Критерии: #1 — записи есть у каждого вошедшего кадра, и тест складывает их join за join в длину собранного файла; #2 — у исключённого кадра записей нет (тот же тест); #3 — повторная запись под тем же роликом заменяет прежнюю, а не удваивает; #4 — весь набор воркера в Docker: 151 passed; #5 — запись стоит сразу за rhythm.fit, сбой записи сборку не ломает (закреплено тестом), фильтр по готовым роликам — на стороне API из TASK-191.
