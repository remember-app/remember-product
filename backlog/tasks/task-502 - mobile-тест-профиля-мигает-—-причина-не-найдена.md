просто видит то, что просочилось из соседа.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## Причина найдена и названа

**Одной фразой:** флак был утечкой в живое api на `localhost:3000`. Тест профиля в своём `afterEach`
возвращает тему и язык, а дерево на тот момент ещё стоит — и `POST /me/language` уходил настоящему
api с подставным токеном. Ответ приходил в следующий тест, схлопывал сессию, и `open()` падал на
`expect(shown()).toBe(true)`: `ProfileScreen` не смонтировался. Отсюда «иногда три, иногда два» —
это гонка по времени.

**Правку в коде вносить не потребовалось:** утечку закрыла TASK-488 (`8c21497`, `vitest.setup.ts:24`)
заглушкой `globalThis.fetch`. Карточка заведена в 00:25, починка легла в 01:57 — то есть карточка
описывала флак, который к моменту её приёмки уже был закрыт. Править поверх чужой починки было бы
угадыванием, поэтому код не тронут.

## Проверено лично, на своём дереве, при живом api на 3000

`projects/api` был запущен (`src/server.ts`, pid 40437), то есть условие для флака выполнялось:

- **guard снят** — файл в одиночку, четыре прогона подряд: `2, 3, 3, 3` упавших. Число гуляет от
  прогона к прогону, ровно как в карточке;
- **guard на месте** — пять прогонов подряд: `25 passed` каждый.

Возврат заглушки — через `cp` с сохранённой копии, `git status` после проверки чист.

## Что в объяснении исполнителя не подтвердилось

Он объяснял утечку тем, что `vi.unstubAllGlobals()` снимает заглушку `fetch` раньше дерева. Замерено:
**не снимает.** `unstubAllGlobals` откатывает только то, что ставил `stubGlobal`; заглушка в
`vitest.setup.ts` — прямое присваивание `globalThis.fetch`, и она переживает `unstubAllGlobals`.
Значит заглушка не снималась никогда, и утечку закрывал именно guard TASK-488, а не порядок в
`afterEach`.

Вывод карточки от этого не меняется — флак найден и подтверждён в обе стороны, — но объяснение
механики было неверным, и оно осталось бы в карточке навсегда.

## Направление «видно сбоку» закрыто замером, а не гипотезой

Каждый тестовый файл получает свой процесс: два файла, печатающих `process.pid`, дали разные pid.
Глобалы, модульный кэш и таймеры между файлами не делятся. Vitest гоняет пул `forks` с изоляцией.

## Отброшено при разбирательстве

- таймеры: `useRealTimers` есть везде, где `useFakeTimers` (23 файла);
- запас `settle()`: 6 раундов `setImmediate` снижались до 2 и до 1 — `25 passed`;
- `CHECK_DELAY_MS = 400` в `src/screens/onboarding/username-form.tsx` обнулён — `25 passed`;
- таймауты: тесты идут 4–47 мс при дефолтных 5000 мс;
- `--no-isolate` даёт 331 красный тест в 44 файлах, но конфигурация проектом не используется.

## Красное, которое не моё — ушло по кругу

При трёх полных прогонах на общем dev первый упал: `tests/kit/large-type-cells.test.tsx`,
«the weekday letters stay whole in their column», таймаут 5402 мс. В одиночку файл мигает сам по
себе: 2 из 3 прогонов красные.

Файл проверен на `e3fc381` — моём последнем коммите: четыре прогона подряд зелёные. Флак принесли
чужие коммиты, слитые после (`TASK-521`, `TASK-524`, `TASK-526`). Не мой и не чинил.

## Осталось непроверенным

- Живое api из `projects/api` не воспроизводилось целиком — снятие guard'а даёт тот же симптом,
  но конкретный ответ настоящего api на подставной токен не наблюдался.
- Не искал, какой именно файл утекает: guard перекрывает это целиком, а не «нет флака — не ищи».
