## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Найдено кодером README api по TASK-253. Воркер при повторе задачи (journal.begin) стирает записи и возвращает этапы в ожидание, ролик при этом остаётся в работе; курсор приложения (наибольший id) остаётся, новые записи получают большие номера — старые остаются на экране. Редкое: нужен временный сбой сборки. Как узнать о повторе — по этапам (вернулись в pending) или по исчезновению записей; решать при разборе.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Приложение замечает повтор сборки по смене времени начала этапа (или пропаже этапа) — признак в воркере ставится и стирается только начинающейся попыткой; журнал сразу читается с начала, без пустого экрана, один сброс на повтор, ложных срабатываний при обычном ходе, готовности, сбое и опоздавшем ответе нет. 12 тестов на обоих записях, красные без правки. Слито в main приложения.
