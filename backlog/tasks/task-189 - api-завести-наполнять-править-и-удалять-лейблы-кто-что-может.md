## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Участник заводит лейбл, кладёт в него выбранные кадры пачкой (или заводит лейбл сразу с кадрами), убирает кадры, переименовывает и удаляет лейбл. Кто что может — по временному правилу, пока человек не ответил по decision-12. Кадры от лейблов не страдают.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Завести лейбл: название, цвет, общий или личный; можно сразу с кадрами — лейбл и его кадры появляются вместе или не появляются вовсе. Пустое название или сверх предела — отказ понятным ответом
- [ ] #2 Положить в лейбл несколько кадров одним запросом: уже лежащий кадр — не ошибка и не дубль; в пачке кадр другого воспоминания или несуществующий — отказ всей пачки, ничего не положено наполовину. Чужой кадр положить можно — он не становится твоим и прав на него не меняет
- [ ] #3 Убрать несколько кадров из лейбла одним запросом; сами кадры остаются в галерее на своих местах
- [ ] #4 Переименовать и перекрасить лейбл. Общий ↔ личный после создания не переключается (макет этого не рисует)
- [ ] #5 Удалить лейбл: лейбл и его связи уходят, кадры остаются в воспоминании нетронутыми, галерея не меняется
- [ ] #6 Права (временное правило по decision-12): общий лейбл переименовывает и удаляет создатель и организатор; класть в общий лейбл может любой, кому можно добавлять; убрать кадр из общего лейбла может создатель лейбла, организатор и тот, кто кадр туда положил; зритель заводит и наполняет только личные, на общих любая запись — отказ «нельзя» тем же ответом, что и у других маршрутов для зрителя
- [ ] #7 Чужой личный лейбл на любую запись (положить, убрать, править, удалить) отвечает «не найдено», как будто его нет; хозяин личного лейбла — только он
- [ ] #8 Выход участника и исключение: его личные лейблы в этом воспоминании уходят вместе с ним, общие остаются, хозяином становится организатор; кадры живут по своему правилу (кадры ушедшего удаляются и пропадают из всех лейблов, чужие кадры в его лейблах остаются в галерее)
- [ ] #9 Всё правило прав — в одном месте кода, помечено как временное по decision-12: когда человек ответит, меняется оно, а не десять маршрутов; те же слова — в README API
- [ ] #10 Автотесты снаружи (через HTTP) на каждый пункт выше, включая «удаление лейбла не трогает кадры», «кадр в нескольких лейблах не дублируется в галерее», «положил пачкой и увидел их там»; весь набор api зелёный в своей тестовой базе
- [ ] #11 В списке лейблов у каждого лейбла сказано, что спрашивающему можно: править (переименовать, удалить) и класть в него кадры — по тому же правилу прав, что и у записывающих маршрутов, чтобы приложению не повторять правило у себя (экран рисует кнопки правки только там, где сервер разрешил)
<!-- AC:END -->
