## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Коллега выдаёт доступ к Google-хранилищу только JSON-ключом служебной учётки, а не парой ключей S3. Сервер должен уметь работать так — с теми же подписанными ссылками на куски для телефона — и не потерять работу с местным MinIO.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Драйвер хранилища выбирается настройкой STORAGE_DRIVER: s3 (по умолчанию — как сегодня, MinIO и S3-совместимые) и google (JSON-ключ из GOOGLE_STORAGE_CREDENTIALS одной строкой, бакет из GOOGLE_STORAGE_BUCKET); имена R2_* и поведение по умолчанию не меняются, стенд человека на маке продолжает работать без правок
- [ ] #2 В режиме google все обращения сервера идут с токеном доступа из JSON-ключа (получение и кеширование токена, обновление до истечения), а подписанные ссылки на куски и на скачивание подписываются закрытым ключом локально (V4 RSA) — так, как это подтвердила живая проверка; протокол между сервером и телефоном (ссылки на куски, ETag, завершение) НЕ меняется
- [ ] #3 Обрыв незавершённых загрузок, удаление, размер файла и повторная выдача ссылок работают в обоих режимах; ошибки Google не теряются и не выводят ключ или токен в лог и ответы; отсутствие или битость ключа при старте в режиме google — громкая понятная ошибка, а не тихая недоступность хранилища
- [ ] #4 Автотесты: прежние зелёные на MinIO; для режима google — модульные тесты на подпись ссылок (каноническая строка проверена по примерам из документации Google), на получение и кеш токена, на форму каждого запроса с подменой fetch; один запускаемый живой контроль режима google (расширение существующего storage:check) на бакете для проверок
- [ ] #5 docs/running.md и docs/media.md описывают режим google: настройки без значений, права служебной учётки (Storage Object User на бакеты), правило бакета про незавершённые загрузки, как запустить живой контроль
- [ ] #6 Все операции драйвера google идут ТОЛЬКО под настроенным префиксом (по умолчанию remember/dev-media/): префикс добавляется в одном месте, любой ключ вне префикса (пустой, с «..», с ведущим «/», с другим префиксом) отклоняется громко до обращения к Google — это касается и удаления, и обрыва загрузок; закреплено тестом, который краснеет, если операция выйдет за префикс; имена объектов неугадываемые (uuid) — проверено по коду создания ключей (оригиналы, превью, музыка), порядковых имён нет

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
НЕ начинать, пока живая проверка (карточка про подпись ссылок на куски) не показала, что схема работает; при провале решает chief. Сервис: projects/api, src/media/r2.ts (сегодня aws4fetch с подписью S3, адресация по пути). Основа — чтение документации Google (2026-09-25): XML API принимает Authorization: Bearer; подпись ссылки V4 GOOG4-RSA-SHA256 без сети закрытым ключом; всё нужное входит в роль Storage Object User на бакете; сервер сам делает начало (POST ?uploads, Content-Length 0) и завершение (POST ?uploadId, тело XML, части по возрастанию) — подписанной ссылкой их сделать нельзя; scope токена devstorage.read_write; локального эмулятора многочастной загрузки нет (fake-gcs-server и storage-testbench её не умеют, MinIO принимает только подпись S3). Реализация подписи и токена — на node:crypto и fetch, без google-auth-library, если это не выходит заметно длиннее; имена настроек как у qe-life (STORAGE_DRIVER=google, GOOGLE_STORAGE_BUCKET, GOOGLE_STORAGE_CREDENTIALS) чтобы значения в инфраструктуре лежали привычно. Стенд человека на маке и его MinIO не трогать: тесты только в своей тестовой базе и своём MinIO.

РЕШЕНИЕ decision-16 (2026-09-25): хранилище ВРЕМЕННОЕ — общий бакет компании cdn.dapp-devs.com; всё наше строго под префиксами remember/dev-media/ (основная) и remember/dev-check/ (проверки), ни одного объекта вне них — чужое рядом, промах дорогой. Бакет публичный, поэтому единственная защита кадра — длина и случайность пути: имена объектов — только неугадываемые (uuid), никаких порядковых имён. Ключ — JSON служебной учётки компании в ~/.remember-secrets.gcs.json (кладёт человек, TASK-347); настройки: GOOGLE_STORAGE_BUCKET=cdn.dapp-devs.com, префикс основной remember/dev-media, префикс проверок remember/dev-check. Перенос на своё хранилище — потом и, возможно: поэтому префикс задаётся настройкой и добавляется в одном месте драйвера (в БД остаются прежние логические ключи).
