## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
doc-03 / doc-11: библиотека из пяти треков — «Яркая», «Тёплая», «Спокойная», «Ночь», «Дорога» (эти имена и порядок — из макета design/screens/MontageMusic.html, он источник правды по названиям); подбираем сами, бесплатные для использования, с записью, откуда трек и под какой лицензией. Плюс — склейки попадают в ритм выбранного трека (библиотечного или своего, из TASK-152 — там music_track_key), а не режутся фиксированной длиной, как сейчас.

Сейчас в TRACKS (montage.py) — три синтезированных тона вместо музыки, осознанная заглушка (ponytail-пометка в коде), а не решение по музыке. Задача:
- расширить список до пяти id/имён по макету; подобрать под каждое настоящий бесплатный трек (без регистрации на сервисе, без оплаты) и записать в README/отдельном файле источник и лицензию каждого. Если по инфраструктурным причинам исполнитель не может закачать сами аудиофайлы в этот прогон — не выдумывать замену: зафиксировать конкретный подобранный трек (ссылка, автор, лицензия) и оставить синтезированный тон на его месте до следующей загрузки, явно пометив в коде, какой трек его должен заменить.
- ритм: точки склейки между кусками — под биты трека (аудио-анализ, например librosa — ISC, дёшево на CPU, см. doc-11), а не фиксированные CLIP_SECONDS/PHOTO_SECONDS; работает и для трека из библиотеки, и для своего, загруженного организатором.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Ветка worktree-agent-a4f8d36ada1b89e3c в сабмодуле projects/montage, коммит 21524d7. Слияние в main — за лидом.

Библиотека (assembly.py): TRACKS стал кортежем из пяти id в порядке макета MontageMusic.html — bright «Яркая», warm «Тёплая», calm «Спокойная», night «Ночь», road «Дорога»; DEFAULT_TRACK не менял (warm), хотя на макете предвыбрана «Яркая» — это решение продукта, не моё. Синтезированные тоны (aevalsrc) удалены целиком: закачаны настоящие файлы, tracks/<id>.mp3, по одному на каждый id. Все пять — Kevin MacLeod с incompetech.com, лицензия CC BY 4.0, прямая ссылка, без регистрации и оплаты; выбирал по машиночитаемому каталогу сайта (pieces.json) по настроению, темпу и длине: Happy Alley, Easy Lemon, Thinking of You, Night Cave, Neo Western. Файлы байт в байт с сайта, не перекодированы, вместе 22 МБ. tracks/README.md держит таблицу «id — имя на экране — трек», источник, ISRC, sha256 каждого файла и готовые строки указания авторства. ВАЖНО для продукта: CC BY требует называть автора там, где ролик показывают, — без этого условие лицензии не выполнено (безатрибуционная лицензия у incompetech платная).

Ритм (новый rhythm.py): четвёртый модуль пайплайна, отсев → ритм → сборка. beats() декодирует трек ffmpeg-ом в 22 кГц wav (libsndfile за librosa не открывает m4a с телефона) и отдаёт биты через librosa.beat.beat_track; fit() подтягивает длину каждого куска так, чтобы на бит легла середина кросс-фейда — место, где склейка слышна. Решения: подгоняется длина уже выбранного куска, а не наоборот, поэтому от музыки не зависит состав ролика и неважно, на каком метрическом уровне услышан пульс; бит выбирается из тех, что дают куску позволительную длину (1.5–6 с, клипу верх задаёт ещё и его файл — новое поле Piece.source_seconds), а не «ближайший с последующей обрезкой» — иначе после упора в рамку шли куски по полторы секунды подряд; последний кусок не трогается. Нет подходящего бита — кусок остаётся своей длины; меньше 8 битов на трек, нечитаемый файл, любая ошибка разбора — пустая сетка и сборка ровными кусками, как раньше. Короткий трек assembly пускает по кругу (-stream_loop -1 вместо aevalsrc фиксированной длины), поэтому сетка битов тиражируется на полчаса вперёд: иначе ролик разъезжался ровно там, где музыка пошла на второй круг.

Свой трек (montage.py): params.music_track_key — ключ файла в бакете (api music_uploads, TASK-152); есть ключ — id библиотеки не читается вовсе. Скачанный файл проходит media._refuse_playlists до первого ffmpeg (чужие байты, та же дверь, что у медиа); не читается или плейлист — отказ без повторов «загруженный трек не читается», шестой в списке.

Зависимость: librosa~=1.0 в requirements.txt (ISC, названа в doc-11) — с комментарием, почему готовая библиотека, а не своя математика. Тянет scipy/numba; образ python:3.12-slim из Dockerfile собирается и импортирует её (проверил сборку отдельно, тесты в контейнере не гонял — они чистят jobs у стенда).

Тесты: 90 зелёных (pytest в worktree против remember_test и MinIO, окружение как у make test-montage). Новый test_rhythm.py — на нарисованном метрономе с известным темпом, без базы и бакета. В test_montage.py: целый ролик под загруженный трек (последняя склейка обязана лечь на бит и ролик обязан стать длиннее ровных 10.5 с), отказ на файле, который не музыка, и проверка, что все пять файлов библиотеки открываются как аудио. Окна длительности в старых тестах заменены на about(duration, ожидаемое) с запасом в секунду: ролик теперь выходит около суммы кусков, а не ровно в неё, — различать три/четыре/пять кусков окно по-прежнему позволяет (проверил: со старой ошибкой из TASK-126 ролик выходит 3.03 с, далеко за окном).

Осталось снаружи задачи: у api свой список id музыки (src/montages/montages.ts, musicTracks = warm/bright/calm) — пока в нём нет night и road, эти два заказать нельзя; нужна отдельная правка в api. Длина ролика теперь зависит от трека и выходит на 5–10% короче target_seconds на треках, где бит не делит три секунды нацело, — target_seconds и раньше был пожеланием, в README это описано.
