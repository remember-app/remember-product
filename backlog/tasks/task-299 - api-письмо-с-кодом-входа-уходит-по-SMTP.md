## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Сервер шлёт письмо с кодом только через Resend, а человек дал ящик по SMTP (отправитель dev@noxlabs.xyz, пароль приложения Google). Письмо с кодом должно уходить этим путём; ни пароля, ни адреса с паролем в репозитории нет.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Письмо с кодом входа уходит через SMTP: сервер, порт, шифрование, пользователь, пароль и адрес отправителя берутся из окружения; поддерживается порт с шифрованием после соединения (587) и сразу зашифрованный (465)

- [ ] #3 Отказ или зависание почтового сервера не подвешивает запрос и не роняет процесс: человек получает понятную ошибку, в логе строка уровня error с причиной и без пароля и без кода

- [ ] #6 Письмо проверено автотестом против настоящего SMTP-сервера, поднятого в тесте (не подменой отправителя): виден адресат, тема, код в теле, язык письма; проверены отказ сервера и таймаут
- [ ] #7 docs/running.md, docs/auth.md, README и .env.example описывают новые настройки без значений; в репозиторий не попал ни один секрет

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Сервис: projects/api. Сегодня: src/auth/mail.ts (Resend через fetch, mailConfigured(), письмо на двух языках уже написано — тексты не менять), используется из src/auth/email.ts, настройки — src/auth/config.ts (env() читает пустое как незаданное). Окружение теперь: SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASSWORD, MAIL_FROM (имена как у соседнего проекта компании qe-life, чтобы значения в инфраструктуре совпадали; в коде их значений быть не должно). Отправитель по контракту — «Remember <dev@noxlabs.xyz>»-вида, задаётся MAIL_FROM. Реальное письмо с настоящим паролем этим кодером не проверяется — пароля у него нет и быть не должно; его посылают при выкатке. Что взять для SMTP-клиента (готовая библиотека или свой) — решает кодер: самодельный протокол с STARTTLS и AUTH — не «пара строк», но новая зависимость должна оправдываться. Миграций нет. Нельзя трогать стенд человека на маке (его база remember, порты, живые процессы) — тесты только в своей тестовой базе.
